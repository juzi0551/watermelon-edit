# 段落生命周期与 UUID 追溯改造 — 独立验收指南

> 本指南面向**全新的验收对象**（不了解本项目历史的工程师/验收方）。
> 按阶段顺序执行即可完成一次独立、可复核的深度验收。
> 验收对象：西瓜审校（Watermelon Edit）全栈项目，段落标识从 `paragraph_idx` 升级为 `paragraph_uuid`，并引入逻辑删除（`is_deleted`）与合并追溯（`merged_into_uuid`）。

---

## 0. 验收准备（15 分钟）

### 0.1 背景速览（必读）

改造的核心主张（验收就是要证明这些成立）：

| 主张 | 说明 |
|---|---|
| P1 | 段落以 `uuid` 为物理锚点，不因插入/删除/合并重排而失效 |
| P2 | 删除 = 逻辑删除（`is_deleted=1, idx=NULL, id=doc:deleted:uuid`），正文过滤展示 |
| P3 | 合并 = 逻辑删除 + `merged_into_uuid` 指针，支持链式追溯（最多 5 层、防环） |
| P4 | 所有段落修改入口对"已合并/已删除"引用透明处理（追溯落点 / 400 拦截） |
| P5 | 删除的段落可恢复（restore），被合并段落不可恢复 |
| P6 | 上传新版本 = 新 document_id；旧版本引用返回 `stale_version` 降级 |
| P7 | 数据库迁移无感：存量库（v12）启动时自动升 v13，数据零丢失 |
| P8 | 前端所有跳转/段号显示经 uuid 对照或状态 API 反推 |

### C1. 新库初始化

```bash
cd backend
venv/bin/python -c "
import os, tempfile
import app.core.database as db
tmp = tempfile.TemporaryDirectory()
db.DB_PATH = os.path.join(tmp.name, 'new.db')

with db.get_conn() as c:
    tables = sorted(r['name'] for r in c.execute(\"SELECT name FROM sqlite_master WHERE type='table'\").fetchall())
```

| # | 场景 | 操作 | 预期 |

| D2.3 | 二次删除幂等 | 再次 DELETE u3 | `{status:"already_deleted"}` |

| D2.5 | 已删段修改拦截 | `PATCH /api/projects/{pid}/paragraphs/{u3}` body `{text:"x", paragraph_uuid:u3}` | HTTP 400，正文未变 |

| D2.8 | 批量合并 | `POST /api/projects/{pid}/paragraphs/merge_batch` body `{paragraph_uuids:[u7,u8,u9]}` | status(u8)/status(u9) → merged → target_uuid u7 |
| D2.9 | 被合并段采纳落点 | `PATCH /api/projects/{pid}/paragraphs/{u6}` body `{text:"新文本", paragraph_uuid:u6}` | 200；响应 `uuid==u5`（修改落到 keep 段）；GET results 中 u5 文本变化 |
| D2.10 | 纯 uuid 采纳 | `PATCH /api/projects/{pid}/paragraphs/{u1}` body `{text:"纯uuid"}` | 200；`uuid==u1`（历史卡片无 idx 场景） |
| D2.11 | 链式追溯 | 手工 UPDATE 构造 B→A、A→C | status(B) → merged → target_uuid==C |
| D2.12 | 跨版本 | 上传新 docx（或 create_document 新版本并 update_project_document） | status(旧版 uuid) → `stale_version` + `version` |
| D2.13 | 图谱接口 | `GET /api/projects/{pid}/character-graph` | nodes/edges/events 含 paragraph_uuid 字段 |
| D2.14 | 清空段落 | `POST /api/projects/{pid}/clean-empty-paragraphs` | 空段消失；**非空段 idx 连续**；errors/章节索引不错位 |

## 8. 常见坑与提示（给验收者）

1. **0-based vs 1-based**：内部 `idx` 从 0 起；前端展示 `+1`。断言时注意区分。
2. **uuid 是短格式**：`generate_id()` 生成的不是标准 36 位 uuid4，长度约 12-13；用 `==` 字符串比较即可，别做格式断言。
3. **测试必须用临时库**：任何"测试污染真实库"现象 = 缺陷（A3.4 已修，验证时留意）。
4. **E2E 用例相互独立**：若某用例依赖前一用例状态 = 测试缺陷。
5. **HTTP 前缀 `/api`**：所有接口带 `/api` 前缀（`app.include_router(..., prefix="/api")`）。
6. **迁移只跑一次**：schema_version 守卫；重复启动幂等。若在真实库验证，务必先备份。
7. **验证入口优先用现成测试**：`test_api_e2e.py` 已覆盖 D 阶段核心场景，人工 curl 仅用于抽查与边界。
