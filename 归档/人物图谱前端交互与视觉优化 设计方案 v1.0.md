# 人物图谱前端交互与视觉优化 设计方案 (v1.0)

> 目标：把人物关系图从「点图看角色」的被动交互，重构为「选角色看邻域」的主动交互——增加角色选择器、节点名称与关系可见性、焦点驱动高亮（ego-network）、视觉差异化，修复"图看得很匀、点上看不到名字、看不出两人关系"三类体验问题。
>
> 范围：主体为 `frontend/src/components/CharacterGraph.jsx` 前端交互与视觉改造；另含一项配套后端改动——校对 prompt 增加「群体展开」规则，解决"多人群体关系只生成以主角为中心的部分边（缺 铜锁↔哈呼）"的漏边问题。

---

## 一、现状问题（代码级定位）

| 用户感受 | 代码根因 |
|---|---|
| 只能点图切换角色 | `selectedNodeId` 仅由 `NodeEvent.CLICK` 驱动（CharacterGraph.jsx:293），侧边栏无角色选择器 |
| 点上没有角色名称 | node label 12px、无衬底，力导向布局下重叠、不显眼（:252, :250） |
| 看不出两人的关系 | 边 label 11px、带 `endArrow` 箭头（无向关系画箭头有误导）、颜色差异小易被忽略（:271, :204） |
| 图看得很匀、无主次 | 节点填充色 = `community_id`（当前单社区全同色）+ 稀疏图中心度全 0 → 节点大小、颜色无差异（:162-166, :178-187） |

## 二、核心交互模型转变

```
旧：点击图节点 → 查看该角色画像
新：选择/点击角色 → 以该角色为焦点 → 图高亮其直接关系邻域（ego-network）
```

所有角色的信息浏览都围绕"焦点角色"组织：焦点节点的画像、它的一跳关系清单、它在图中的邻域高亮，三者联动。

## 三、详细设计

### 3.1 角色选择器（解决"只能点图"）

- 侧边栏顶部新增焦点角色 `Select`（`showSearch`，按主名/别名过滤）。
- 选中后 `setSelectedNodeId`，触发 3.3 的邻域高亮。
- 图上点击节点仍可切换焦点（保留原行为，二者同源）。
- 侧边栏新增**「关系清单」**区块：列出焦点角色的所有直接边：
  ```
  • A —family→ 智星（确立于第 194 段）
  • B —friend→ 智星（确立于第 292 段）
  ```
  每项可点击：① 跳转到确立段落；② 点击对端角色名切换焦点。

### 3.2 节点名称可见

- node 样式：`labelFontSize: 13`，新增 `labelBackground: true`（白色/半透明衬底），`labelPlacement: 'bottom'` 保留。
- 确保名称在任何背景色上都可读。

### 3.3 焦点驱动高亮（ego-network）

- 维护 `focusId` 状态（与 `selectedNodeId` 合并）。
- 焦点切换时对图元素执行 `setElementState`：
  - **焦点节点**：`highlight`（放大、金色描边、不透明）。
  - **一跳邻居节点 + 焦点直接边**：`highlight`（邻居保持亮度，边加粗、不透明）。
  - **其余节点与边**：`dark`（opacity ~0.15）。
- 无焦点（初始）时全量正常显示。
- 复用现有 `node.state.highlight/dark` 与 `edge.state.highlight/dark` 定义（已存在，仅需补焦点节点的放大尺寸状态）。

### 3.4 边关系可见

- **去掉 `endArrow`**：关系为无向语义，箭头误导（当前 `endArrow: true`）。
- 边 label 常显类型中文名：友好盟友 / 敌对阵营 / 倾慕情侣 / 亲情家族 / 中立接触（`RELATION_TAG_LABELS` 已有），颜色 = 类型（`RELATION_EDGE_COLORS` 已有）。
- 边宽 = strength（已实现，v1.2 计划）。
- 悬停边 → `Tooltip`（G6 `EdgeEvent.POINTER_ENTER/LEAVE`）展示 `description` + 确立段 + 强度。
- 点击边 → 关系详情（可跳转确立段落）。

### 3.5 视觉差异化（解决"很匀"）

- 节点填充色改为**优先 role**：主角金 `#faad14` / 反派红 `#f5222d` / 配角蓝 `#1890ff` / 次要灰 `#8c8c8c`（`ROLE_STROKES` 已有，扩为 fill）。
- 社区色降级为描边（`stroke = COMMUNITY_COLORS[community_id % n]`），仅当项目多社区时提供分组信息。
- 节点大小：保留中心度映射 `28 + centrality*48`，焦点节点在此基础上再放大（如 ×1.3）。
- 画布左下角新增**图例 Legend**（纯 DOM 覆盖层）：
  - 角色类型色块 + 名称
  - 关系类型色块 + 名称
  - 边宽 = 互动强度说明

### 3.6 最短路径交互优化

- 起点/终点 `Select` 加 `showSearch`（角色多时便于搜索）。
- 移除"点击节点自动塞 source/target"的逻辑（CharacterGraph.jsx:298-305）：点击只做聚焦，选点统一走下拉，避免误触。

### 3.7 布局调整

```
┌──────────────────────────────────────────────────────┐
│ 时间轴 Slider（不变）                                  │
├──────────────┬───────────────────────────────────────┤
│ G6 画布       │ 侧边栏（宽 360）                        │
│  (焦点邻域高亮)│  1. 焦点角色 Select（showSearch）        │
│  (图例覆盖层)  │  2. 全局画像（description）             │
│              │  3. 关系清单（直接边，可跳转/切焦点）      │
│              │  4. delta_summary 履历链               │
└──────────────┴───────────────────────────────────────┘
```

## 四、配套改动：校对 prompt「群体展开」规则（后端）

> 背景：实测项目 `802661d60d58` 中，原文「他们三人便成了形影不离的好伙伴」（智星/铜锁/哈呼），模型只生成了 `智星↔铜锁`、`智星↔哈呼` 两条 friend 边，**漏了 `铜锁↔哈呼`**——群体关系被当成"以主角为中心"的辐射，而非完整的每对边。此改动修复"该有的边没有"。

### 4.1 规则文本（`DEFAULT_SYSTEM_PROMPT_PROOFREAD` 的 `relationship_events` 条款）

在现有「关系状态声明」规则上新增第 3 条：

```
3. **群体展开**：若文本明确描述多个角色同属一个群体或亲密关系（如“三人形影不离的好伙伴”“三兄弟”“一家人”“同门”），必须为群体内每一对角色分别输出一条 relationship_events，确保 N 人群体生成 C(N,2) 条边，不得遗漏任何一对、不得只输出主角相关的对。
```

### 4.2 JSON 示例（三人三角形）

在 `relationship_events` 示例中补充三人成组写法：

```json
"relationship_events": [
  {"from": "智星", "from_character_id": "a1b2c3d4e5f6", "to": "铜锁", "to_character_id": "78f9a1b2c3d4", "type": "friend", "description": "三人形影不离的好伙伴", "paragraph_idx": 25},
  {"from": "智星", "from_character_id": "a1b2c3d4e5f6", "to": "哈呼", "to_character_id": "91ab2c3d4e5f", "type": "friend", "description": "三人形影不离的好伙伴", "paragraph_idx": 25},
  {"from": "铜锁", "from_character_id": "78f9a1b2c3d4", "to": "哈呼", "to_character_id": "91ab2c3d4e5f", "type": "friend", "description": "三人形影不离的好伙伴", "paragraph_idx": 25}
]
```

### 4.3 生效方式

- 修改代码常量 `DEFAULT_SYSTEM_PROMPT_PROOFREAD`。
- **settings 表**存有旧版 prompt（全局、`INSERT OR IGNORE` 不覆盖），需在设置页点「恢复默认模板」或由后端刷新该设置后方可生效。

## 五、边界与交互细节

| 场景 | 处理 |
|---|---|
| 图节点很少（<5） | 邻域高亮照常，无焦点时全亮 |
| 焦点角色无任何边（孤立节点） | 仅焦点高亮，关系清单为空并提示"暂无直接关系" |
| 切换时间轴 Slider | 重置高亮与焦点为默认（中心度最高角色） |
| 最短路径高亮与焦点高亮共存 | 两者都用 `highlight/dark` state，冲突时以"最短路径结果"优先（点击"重置高亮"后恢复焦点态） |
| 边无 description | 悬停仅显示类型 + 确立段 + 强度 |

## 六、验证计划

1. `npm --prefix frontend run build` 零错误。
2. 手动验证：
   - Select 搜索切换焦点，邻域高亮正确、非邻居置灰。
   - 节点名称清晰可读；边类型中文标签可见、无箭头。
   - 图例颜色与实际渲染一致；多 role 时节点填充色正确区分。
   - 关系清单项可跳转段落、可切换焦点。
   - 最短路径求解后"重置高亮"恢复焦点态。
